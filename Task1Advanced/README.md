# Задание 1. Модульная инфраструктура для нескольких сред

Terraform-модуль `vm` разворачивает виртуальную машину с указанными ресурсами. При создании ей назначается загрузочный диск на основе выбранного образа, отдельный дополнительный диск и публичный IP-адрес.

## Входные параметры

| Параметр | Тип | Назначение |
|---|---|---|
| `vm_name` | `string` | Имя виртуальной машины |
| `cores` | `number` | Число ядер процессора |
| `memory` | `number` | Размер оперативной памяти в ГБ |
| `disk_size_gb` | `number` | Вместимость дополнительного диска в ГБ |
| `subnet_id` | `string` | Идентификатор подсети |
| `ssh_key` | `string` | Публичная часть SSH-ключа |

## Результаты работы

Модуль возвращает следующие значения:

- `vm_id` — идентификатор созданной виртуальной машины;
- `vm_name` — её имя;
- `internal_ip` — внутренний IP-адрес;
- `external_ip` — внешний IP-адрес, если он был назначен;
- `additional_disk_id` — идентификатор дополнительного диска.

## Развёртывание окружения

Для `dev`, `stage` и `prod` предусмотрены отдельные каталоги и файлы переменных. Ниже приведён пример запуска для `dev`.

1. Укажите значения параметров в `envs/dev/dev.tfvars`:

   ```hcl
   ssh_key   = ""
   subnet_id = ""
   ```

2. Инициализируйте рабочий каталог Terraform:

   ```sh
   terraform init
   ```

3. Проверьте, какие изменения будут выполнены:

   ```sh
   terraform plan -var-file=envs/dev/dev.tfvars
   ```

4. Создайте ресурсы:

   ```sh
   terraform apply -var-file=envs/dev/dev.tfvars
   ```

Для других окружений используйте тот же порядок действий, подставив путь к нужному файлу: `envs/stage/stage.tfvars` или `envs/prod/prod.tfvars`.
